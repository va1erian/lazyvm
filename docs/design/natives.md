# The native contract between `lazyrt` and the VM

Every `native` method in `java/lazyrt` is implemented in Rust in
`crates/natives`, keyed by `class.name(descriptor)`. This file is the
contract. Adding or changing a native means changing it here, in the Java
declaration and in Rust, in the same PR. An unknown native throws
`UnsatisfiedLinkError` naming the method.

Rules for `lazyrt` Java code, until the stage named:

- No lambdas or method references until S4 (they need `invokedynamic`).
- No `assert` until S4.
- Helpers are package-private or live in `lazy.internal`; no new public or
  protected API in `java.*` (shared rule 2).
- Line separator: `System.lineSeparator()` comes from the
  `line.separator` property, which is `"\r\n"` on Windows and `"\n"` elsewhere.

## VM-known fields

The VM reads and writes these fields by name. Keep their names and types.

| Class | Field | Use |
|---|---|---|
| `java.lang.String` | `private final char[] value` | The UTF-16 contents; the VM creates strings by filling it |
| `java.lang.String` | `private int hash` | Cached hash, 0 when not computed |
| `java.lang.Class` | `private transient int vmClassId` | The VM's class id for this mirror |
| `java.lang.Throwable` | `private transient Object backtrace` | Frames recorded by `fillInStackTrace0` (an `int[]` the VM owns) |
| `java.lang.Throwable` | `private String detailMessage` | Set by the VM when it throws with a message |
| `lazy.gfx.Event` | `public int type, key, x, y, button`, `public char ch` | Filled by `Window.poll0` |

## VM-called methods

The VM calls these Java methods from natives, by name and descriptor.

| Class | Method | Use |
|---|---|---|
| `lazy.ui.Ui` | `private static void dispatch(int id, int kind)` | The one upcall per widget message, from inside `run0`'s loop (docs/ui.md) |

## Natives

### `java.lang.Object`
- `public final native Class<?> getClass()`
- `public native int hashCode()` (identity hash)
- `protected native Object clone() throws CloneNotSupportedException` (arrays and `Cloneable`; shallow)
- `public final native void notify()`, `public final native void notifyAll()`
- `public final native void wait(long timeout) throws InterruptedException`

### `java.lang.Class`
- `public native String getName()` (binary name with dots; arrays as `[I`, `[Ljava.lang.String;`)
- `public native boolean isInstance(Object obj)`
- `public native boolean isAssignableFrom(Class<?> cls)`
- `public native boolean isInterface()`, `isArray()`, `isPrimitive()`
- `public native Class<? super T> getSuperclass()`
- `public native Class<?> getComponentType()`
- `public native int getModifiers()`
- `static native Class<?> getPrimitiveClass(String name)` (`"int"`, `"void"`, ...)
- `private static native Class<?> forName0(String name, boolean initialize) throws ClassNotFoundException`
- `public native boolean desiredAssertionStatus()` (`-ea`, application classes only)
- `private native T[] getEnumConstants0()` (calls the enum's static `values()`)

### `java.lang.System`
- `public static native void arraycopy(Object src, int srcPos, Object dest, int destPos, int length)`
- `public static native long currentTimeMillis()`
- `public static native long nanoTime()`
- `public static native int identityHashCode(Object x)`

### `java.lang.String`
- `public native String intern()`

### `java.lang.Throwable`
- `private native void fillInStackTrace0()`: records the current frames in
  `backtrace`, skipping the frames of `fillInStackTrace`/`fillInStackTrace0`
  and of the throwable's own constructors.
- `private native StackTraceElement[] getStackTrace0()`: builds the elements
  from `backtrace` (an empty array if there is none).

### `java.lang.StrictMath`
`public static native double` `sin`, `cos`, `tan`, `asin`, `acos`, `atan`,
`exp`, `log`, `log10`, `sqrt`, `cbrt`, `ceil`, `floor`, `rint`, `sinh`,
`cosh`, `tanh`, `expm1`, `log1p` (one `double`), and `atan2`, `pow`,
`hypot`, `IEEEremainder` (two `double`s). They call the `libm` crate, which
is not bit-identical to fdlibm (see "Known differences from Java 8").

### `java.lang.Float` and `java.lang.Double`
- `public static native int floatToRawIntBits(float value)`
- `public static native float intBitsToFloat(int bits)`
- `public static native String toString(float f)`
- `public static native float parseFloat(String s) throws NumberFormatException`
- `public static native long doubleToRawLongBits(double value)`
- `public static native double longBitsToDouble(long bits)`
- `public static native String toString(double d)`
- `public static native double parseDouble(String s) throws NumberFormatException`

### `java.lang.Character`
All answers come from `crates/natives/data/unicode.bin`, generated by
`tools/unicode.py` from what the Java 8 oracle answers for every code point
(format: `crates/natives/src/unicode.rs`). Every native takes a code point, and
a code point outside 0..=0x10FFFF is "unassigned" (type 0, directionality -1,
identity case mapping, -1 digit and numeric value).
- `public static native boolean` `isLetter`, `isDigit`, `isLetterOrDigit`,
  `isWhitespace`, `isUpperCase`, `isLowerCase`, `isTitleCase`, `isSpaceChar`,
  `isAlphabetic`, `isIdeographic`, `isMirrored`, `isDefined`,
  `isIdentifierIgnorable`, `isJavaIdentifierStart`, `isJavaIdentifierPart`,
  `isUnicodeIdentifierStart`, `isUnicodeIdentifierPart` (all `(int codePoint)`)
- `public static native int` `getType`, `toUpperCase`, `toLowerCase`,
  `toTitleCase`, `getNumericValue` (all `(int codePoint)`)
- `public static native byte getDirectionality(int codePoint)`
- `public static native int digit(int codePoint, int radix)`
The `char` overloads, `isISOControl`, `forDigit`, the general category and
directionality constants and the deprecated `isSpace`, `isJavaLetter` and
`isJavaLetterOrDigit` are Java.

### `java.lang.StringCase` (package-private)
Used by `String.toUpperCase` and `toLowerCase`, with or without a `Locale`
(the no-argument forms use `Locale.getDefault()`), for what one-to-one mapping
cannot do. The language of the locale picks the rules: `tr` and `az` (dotted
and dotless i), `lt` (dot above kept on a lower-case i before an accent, dropped
after a soft-dotted letter in upper case, but only once an earlier character has
changed case, U+0130 included), anything else is the root locale.
Those rules are plain Java in `CaseLocale`; the mark sets they look past are
`CaseMarks.java`, generated by `tools/case_marks.py` from the oracle (`--check`
re-verifies). Only the language is read, so `tr_TR` and `tr` agree. `Locale`
itself changes case with ASCII-only rules, as the oracle does, so a Turkish
default locale cannot corrupt a language code. `URI` and `File` fold case with
`Locale.ROOT`. No known differences: a scan of every code point in the dotted
contexts and several million random strings over 28 locales agree with the
oracle (`StringCaseLocale` holds the rows). The soft-dotted set must be probed
with a cased letter in front, or letters without upper case (U+1D62, U+2071)
are missed.
- `static native int special(int cp, boolean upper, int index)`: code point
  `index` of the multi-code-point mapping of `cp` (`ß` to `SS`, `ŉ`, the
  ligatures, the Greek iota-subscript forms; `İ` to `i` U+0307 in lower case),
  or -1 when there is none or `index` is past its end
- `static native int step(int state, int cp, boolean after)` and
  `static native int mask(int which)`: the two small automata that decide
  whether a capital sigma lowercases to the final form (see `unicode.rs`)
The oracle's final-sigma rule depends on the neighbours and is not Unicode's:
only a few characters are skipped between the cased letter and the sigma, a
digit after a cased letter keeps the context, U+0345 behaves differently
after a digit, and so on. `tools/unicode.py` learns it by probing the oracle
(8 states before the sigma, 6 after it, 17 classes of code point) and checks
it on 20,000 random strings; `CaseMapping` repeats the check on the VM.
`toUpperCase` returns a new string for U+0130 even though it maps to itself,
like the oracle.

### `java.lang.Thread`
- `public static native void sleep(long millis) throws InterruptedException`
  (until S6 `currentThread()` is plain Java returning one main thread)

### `lazy.internal.VM`
- `public static native String getProperty(String key)` (null when unset)
- `public static native void exit(int status)`
- `public static native void gc()`
- `public static native long freeMemory()`, `totalMemory()`, `maxMemory()`
- `public static native int availableProcessors()`
- `public static native long entropy()`: 64 bits that differ on every call and
  in every run. The platform hashes the wall clock (full resolution), the
  monotonic clock and a call counter with keys the OS random source gives
  once per process. It seeds `new Random()` and `UUID.randomUUID()`
  (`design/util.md` R3, `design/util-data.md` U8); it is not a cryptographic
  generator.
- `public static native byte[] getResource(String name)` (null when absent)
- `public static native boolean isBootClass(Class<?> c)`
- Java, called by the VM: `static void uncaught(Throwable t)` prints
  `Exception in thread "main" ` and the stack trace to `System.err`.

### `lazy.internal.ConsoleOutputStream` and `ConsoleInputStream`
- `private static native void write0(int fd, byte[] b, int off, int len)` (fd 1 or 2)
- `private static native void flush0(int fd)`
- `private static native int read0(int fd, byte[] b, int off, int len)` (fd 0; -1 at end)
- `private static native int available0(int fd)`: always 0, since a console or
  pipe cannot say how much is ready without blocking.

`System.in` is a `java.io.BufferedInputStream` over `ConsoleInputStream(0)`,
as on Java 8 (io.md I1): it supports mark and reset, returns -1 at every
read after the end, and is "Stream closed" after `close()`.

Bounds are checked in Java before the native is called; the VM checks them
again and throws `IndexOutOfBoundsException` rather than trusting them.

### `lazy.gfx.Window` and `lazy.gfx.Image` (docs/gfx.md)
- `private static native int open0(String title, int width, int height)`: a
  handle (never 0) for a window of that client size in pixels, at most 2^25
  pixels in all (`IllegalArgumentException` above); `-Dlazy.gfx` picks the
  backend. `IllegalStateException` when there is no window system or the
  window cannot be created.
- `private static native void present0(int handle, int[] rgb, int width, int height)`
- `private static native boolean poll0(int handle, Event e)`: fills `e`'s
  `type`, `key`, `ch`, `x`, `y` and `button`, or returns false.
- `private static native boolean isOpen0(int handle)`: false for a handle that
  names no window (closed, or never opened).
- `private static native int size0(int handle, int axis)` (0 width, 1 height)
- `private static native int[] capture0(int handle)`: allocated from the heap
  (so `-Xmx` applies) before the pixels are copied; black where nothing of the
  current size was presented.
- `private static native void setTitle0(int handle, String title)`
- `private static native void close0(int handle)`: an unknown handle is ignored.
  The window is destroyed in every case; `IllegalStateException` if the
  headless dump (`-Dlazy.gfx.dump`) cannot be written, which is why
  `Window.close` drops its handle before calling it.
- `private static native int[] decodePng0(byte[] data, int[] size)`: ARGB
  pixels, with width and height written to `size[0]` and `size[1]`;
  `IOException` for a malformed file, one over 2^24 pixels (64 MiB as ARGB),
  or one whose undecoded row is over 1 MiB. iCCP and text chunks are skipped
  unread. The result array is allocated from the header's size before
  decoding.

Handles name entries in a table owned by the VM thread. Except where noted
above, an unknown handle is `IllegalStateException`. Sizes are checked in Java
and again in Rust.

### `lazy.ui.Ui` (docs/ui.md; S9-02 spike)
These live in `crates/natives-ui` and are registered only by `lazyvm-ui`;
under `lazyvm` they are missing, and `Ui.run` turns the
`UnsatisfiedLinkError` into `IllegalStateException`.
- `private static native void run0(String title, int width, int height, int[] ops, Object[] strings)`:
  builds the window from the op list (`crates/xui-bind/src/tree.rs`; every
  `strings` element a `String`) and runs it until it closes, calling
  `Ui.dispatch` for each message with the VM lent to the loop
  (`vm::interp::with_lent`). Sizes are 1 to 8192. A malformed op list, a
  second call in the process, or no window host is `IllegalStateException`;
  an exception thrown by `dispatch` stops the loop, and `run0` rethrows it.
  `-Dlazy.ui=headless` uses xui's offscreen backend; with it,
  `-Dlazy.ui.clicks=<n>` clicks the first listened-to button `n` times and
  `-Dlazy.ui.dump=<file>` writes the last frame as a binary PPM.
  `-Dlazy.ui.stats=true` prints the build time, upcalls and changes on stderr.
- The op list is the tree in pre-order; every node starts with its opcode
  and the registry id Java gave it (ids are unique; `strings` indexes are
  into the `strings` array; lengths are 0 to 32768; layouts nest at most 16 deep):
  `1 id padding gap n` (column) or `2 id padding gap n` (row), then its `n`
  children; `3 id text` (label); `4 id text click` (button, `click` 1 when
  Java listens). The root is a column or row, and nothing may follow it.
  `Ui.dispatch` receives event kind 1 for a click.
- `static native void setText0(int id, String text)`: a label's or button's
  text; `IllegalStateException` for an id that names no mounted widget.

### `lazy.gfx.Surface` (docs/gfx.md)
Every native gets the surface as its first seven arguments: its `int[]`, its
width and height, and its clip as `x0, y0, x1, y1` (far edges excluded). Rust
checks them again: an array shorter than `width * height`, a negative size or
a clip outside the surface is `IllegalArgumentException`. All drawing is cut
to the clip; no coordinate overflows.
- `private static native void fill0(int[] px, int w, int h, int cx0, int cy0, int cx1, int cy1, int x, int y, int rw, int rh, int argb, boolean blend)`:
  paints `argb` by its alpha, or writes it as it is when `blend` is false
  (`clear`). `rect` is four `fill0` calls in Java.
- `private static native void line0(int[] px, int w, int h, int cx0, int cy0, int cx1, int cy1, int x0, int y0, int x1, int y1, int argb)`
- `private static native void blit0(int[] px, int w, int h, int cx0, int cy0, int cx1, int cy1, int[] src, int sw, int sh, int sx, int sy, int bw, int bh, int dx, int dy, int flags, int key, int keyColor, int solid)`:
  flags other than the five `Surface` constants are `IllegalArgumentException`;
  a non-empty source rectangle outside `src` is `IndexOutOfBoundsException`,
  even where the clip hides it.
- `private static native void blendMask0(int[] px, int w, int h, int cx0, int cy0, int cx1, int cy1, int[] mask, int rgb, int strength)`:
  a mask shorter than `w * h` or a strength outside 0 to 255 is
  `IllegalArgumentException`.

`blit0` and `blendMask0` copy the part they read into a per-thread buffer
first, since the heap lends one array at a time; failing to grow it is
`OutOfMemoryError`.

## Known differences from Java 8

- `StrictMath` (and `Math`, which delegates to it) gives `libm`'s results, not
  fdlibm's: 11 functions differ from Java 8 by 1 to 3 ulps on a small share of
  inputs (`atan2`, `cbrt`, `log10`, `hypot`, `tanh`, `cos`, `sin`, `log`,
  `cosh`, `sinh`, `log1p`); the other 12 matched on every input measured.
  The table and how it was measured are in [`decisions.md`](../decisions.md)
  D13.
- A `NoClassDefFoundError` for a class missing from the class path has no
  cause; Java 8's carries a `ClassNotFoundException` from its class loader.
  Tests print only the error's class and message.
- `PrintStream` and `PrintWriter` over a stream make the same overridable
  calls as Java 8 (`tests/java/util/PrintCalls`, `WriterBlocks`), with these
  known exceptions, none of which changes the bytes of an ordinary stream:
  - the number of `write`/`flush` calls reaching the underlying
    `OutputStream` can differ;
  - Java 8's `close` runs a second time from inside itself, so a wrapped
    stream is closed twice; LazyVM closes it once;
  - each `write(byte[],int,int)` gets a fresh array, where Java 8 reuses one
    buffer per stream, so a subclass whose `write` prints again sees its
    array overwritten on Java 8 only. For the same reason, after a
    subclass's `write` throws, Java 8 sends the text left in that buffer
    again on the next call; LazyVM does not.
  - when a subclass's `write` throws while `close` writes a held half of a
    surrogate pair, Java 8 is left half closed (text is refused, but raw
    `write`, `flush` and `checkError` still reach the stream); LazyVM treats
    the stream as closed.
